# DeepSeek provider tool/schema probe

On 2026-09-18, the probe called `deepseek/deepseek-v4.1-flash` once through
every unique OpenRouter provider endpoint. It used the OpenAI Agents SDK with:

- a `double_number(value: int)` function tool;
- an explicit instruction that the tool must be called with `21`;
- `tool_choice="auto"`;
- `DummyResult`, a Pydantic final-output type;
- native structured output generated by the SDK; and
- each provider pinned with fallbacks disabled.

There were 20 unique providers across 21 endpoints. No provider completed the
whole tool-then-structured-output loop correctly.

| Outcome | Providers |
|---|---|
| Skipped tool; returned schema-valid answer | DeepInfra, Fireworks, Modal, Morph, Parasail, Phala, Venice, Wafer |
| Called tool; final output failed Pydantic parsing | DigitalOcean, Makora, Relace, Together |
| Request rejected | Alibaba, AtlasCloud, GMICloud, Novita, SiliconFlow, StreamLake |
| Endpoint unavailable under current account/rate limits | BaseTen, DeepSeek |

The skipped-tool providers returned `tool_was_used: true` despite the harness
recording no tool execution. The request-rejection group mostly rejected strict
`json_schema` output despite several endpoints advertising the relevant
parameters. BaseTen returned HTTP 429. DeepSeek's own endpoint was excluded by
the account's current data-policy settings.

This is one sample per provider. It establishes protocol behavior for these
requests, not a statistical tool-use rate.

Run from the repository root:

```bash
uv run python docs/analysis/provider-tool-schema-probe-2026-09-18/run.py
```
